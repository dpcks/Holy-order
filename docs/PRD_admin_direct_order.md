# [PRD] 관리자 수동 주문 추가 기능 (Admin Direct Order)

## 1. 개요 (Overview)
- **목적**: 스마트폰 사용에 익숙하지 않은 교인(어르신 등)이 구두로 주문할 경우, 관리자가 직접 시스템에 주문을 입력하여 전체 주문 현황 및 매출 관리에 누락이 없도록 함.
- **위치**: 관리자 실시간 주문 관리 화면 (`AdminOrderManagement.tsx`)

## 2. 사용자 인터페이스 (UI/UX)
- **진입점 (Entry Point)**: 
  - 실시간 주문 관리 화면 우측 하단에 플로팅 액션 버튼(FAB) 추가 (`+` 아이콘).
  - 버튼 클릭 시 '주문 추가' 모달(Modal) 또는 드로어(Drawer) 오픈.
- **주문 추가 모달 (Add Order Modal)**:
  - **주문자 정보 (선택)**: 주문자 이름 (미입력 시 '현장 주문' 등으로 처리)
  - **메뉴 선택**:
    - 메뉴 이미지는 제외하고 텍스트 리스트 형태(빠른 입력 목적).
    - 메뉴명과 가격 표시.
  - **옵션 선택**: 
    - 수량 증감 버튼 (+, -)
    - **텀블러 할인 옵션** (체크박스 또는 버튼형 토글)
  - **결제 정보 (옵션)**:
    - 현장 주문이므로 결제 상태(결제완료-현금/계좌이체 등)를 관리자가 바로 확정할 수 있도록 제공.
  - **액션 버튼**: `취소`, `주문 추가`

## 3. 기능 요구사항 (Functional Requirements)
1. **메뉴 목록 조회**: 현재 활성화(판매 중)된 메뉴 목록을 가져와서 선택지로 제공.
2. **금액 자동 계산**: 선택한 메뉴의 단가, 수량, 텀블러 할인을 적용하여 총 결제 금액 실시간 표시.
3. **주문 생성 (API)**:
   - 주문 생성 후 실시간 현황에 즉시 반영 (WebSocket / Polling).
4. **결제 로그 연동**: 관리자가 수동으로 추가한 내역도 매출 및 정산(Payment Logs)에 정상적으로 집계.

## 4. 데이터베이스 및 백엔드 고려사항 (Backend & DB)
- **주문자(User) 처리**: `user_id`를 필수가 아닌 선택(Nullable)으로 변경하거나, 현장 주문용 'Guest' ID를 할당할지 결정해야 합니다.
- **결제 수단 로깅**: 일반적인 사용자 주문(무통장입금 대기 등)과 달리, 현장 주문은 '현금' 혹은 '현장 계좌이체 확인'이 주를 이루므로 이에 맞는 Payment status 처리가 필요합니다.

## 5. 엣지 케이스 (Edge Cases)
- **중복 클릭 방지**: 버튼 연타로 인한 중복 결제/주문 방지 (Disable 처리).
- **디저트류 텀블러 할인 예외**: 텀블러 할인이 적용되지 않는 메뉴(예: 쿠키, 케이크 등)에 대한 할인 선택 제한.
